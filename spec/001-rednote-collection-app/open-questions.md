# 需要讨论的问题

日期：2026-06-22

## 产品边界

1. 第一版按可能上架或一定量网络传播设计，但同步链路仍先做技术验证闭环。
2. 已接受用户在 App 内 WebView 重新登录小红书。
3. 第一版更重视「同步成功率」还是「分类体验」？
4. 是否需要保留原始收藏顺序？
5. 是否需要支持手动创建文件夹和拖拽移动笔记？

## 技术边界

1. 是否接受非官方 Web 接口随时失效的风险？
2. 登录 Cookie 是否只允许存在 WebView CookieStore，不进入 Native 数据库？
3. 第一版分类已确定使用规则分类 + 「待整理」兜底，暂不调用云端 LLM。
4. 第一版先不用 embedding。
5. 是否需要后端服务，还是第一版坚持纯端侧？
6. 已确定笔记下架、隐藏、取消收藏时先软删除，活跃视图隐藏，后续由用户或维护任务清理。
7. 已确定新增笔记不符合现有分类时，先聚合成一批候选分类再让用户确认。

## 合规与隐私

1. 是否明确限定只同步用户自己的收藏？
2. 是否需要在 App 内提供「清除所有本地数据」？
3. 是否需要对本地数据库加密？
4. 如果未来上架，是否接受因为第三方平台非官方接入导致审核受阻？
