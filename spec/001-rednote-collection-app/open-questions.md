# 需要讨论的问题

日期：2026-06-22

最近更新：2026-08-27

## 已确认决策

1. 第一阶段面向个人及小范围内测，不以应用商店上架为近期目标。
2. 已接受用户在 App 内 WebView 重新登录小红书，并接受非官方 Web 接口可能失效的技术风险。
3. 第一阶段优先验证自动分类体验。
4. 自动分类采用固定一级分类、受控二级自动创建和多标签模型，详见 [`../002-constrained-auto-classification/spec.md`](../002-constrained-auto-classification/spec.md)。
5. Embedding 不参与分类决策；DeepSeek 以受限结构化输出完成分类。
6. 默认增量稳定；全量重排由用户主动触发并先展示预览。
7. Cookie 只保留在 WebView CookieStore，不进入 Native 数据库。
8. 笔记下架、隐藏或取消收藏时先软删除，活跃视图隐藏。
9. 人工分类结果优先，自动流程不得覆盖。
10. “其他”是正式分类，“待整理”是模型失败或低置信度的临时状态。

## 仍需讨论：产品体验

1. 是否需要保留原始收藏顺序？
2. 人工移动二级分类采用拖拽、批量选择还是两者都支持？
3. 是否需要导出 Markdown、Obsidian 或 CSV？
4. 是否需要多账号支持？

## 仍需讨论：技术边界

1. 第一版是否坚持纯端侧，还是需要自有后端代理模型调用？
2. 分类批次大小、超时和重试参数需要通过真实数据校准。
3. 同义标签归一与二级分类近义检测的实现方式需要技术验证。

DeepSeek API Key 已确定使用 Android Keystore 管理的 AES-GCM 密钥加密存储，并对旧明文配置做一次性迁移。

## 仍需讨论：隐私

1. 本地数据库第一版是否加密？
2. 分类请求前是否需要逐次展示待发送字段，还是首次授权后持续生效？
