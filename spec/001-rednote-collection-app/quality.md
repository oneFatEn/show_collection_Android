# 性能与数据安全要求

日期：2026-06-22

## 目标

第一版必须同时满足两个底线：

- 性能：数千到数万条收藏仍能顺畅浏览、同步和分类。
- 数据安全：登录态不出 WebView，长期本地数据最小化，用户可以清除自己的数据。

## 性能验收标准

- 分类首页首屏只加载分类摘要，不加载全部笔记。
- 分类内列表使用分页或懒加载，单次查询只返回当前屏幕及预取窗口需要的数据。
- Room 查询必须使用索引；禁止 UI 层全量扫描后再分组、排序或过滤。
- 同步写库按页批量事务提交，不能每条笔记单独提交事务。
- 新增笔记才触发规则分类；存量笔记不在每次同步时重复分类。
- 封面图使用缩略图和磁盘缓存，列表中不加载原图。
- JSBridge 传输按页或分片，避免一次性传输超大 JSON。
- 展示缓存和图片缓存有清理策略，不能无限增长。

## 数据安全验收标准

- Cookie 只保存在 WebView CookieStore，不写入 Room、DataStore、日志或崩溃上报。
- Native 层只保存笔记 ID、分类关系、同步状态和轻量展示缓存。
- 发布版本不长期保存完整接口响应、完整 raw JSON、完整正文、大图、评论和互动数据。
- 日志只允许记录阶段、数量、错误类型和脱敏错误码。
- 设置页必须提供：
  - 退出小红书登录。
  - 清除本地索引和分类关系。
  - 清除展示缓存。
  - 清除图片缓存。
- 默认排除 Android Auto Backup 中的数据库、WebView 登录态和图片缓存。
- WebView JSBridge 必须校验来源、action、字段类型和 payload 大小。
- 如果未来引入云端 LLM、云同步或崩溃上报，必须先新增隐私授权和字段白名单。

## 数据保留策略

- `Note`、`Category`、`NoteCategory`：核心数据，用户主动删除前保留。
- `NoteMetadataCache`：轻量展示缓存，可过期、可清理、可重建。
- 图片磁盘缓存：可过期、可清理，不作为业务数据。
- `SyncState`：保留最近一次同步状态和必要错误摘要。
- 软删除笔记：活跃视图隐藏，保留状态记录；后续可由用户手动清理。

## 禁止事项

- 禁止把 Cookie 复制到 Native 数据库或上传到服务端。
- 禁止在日志中打印完整接口响应、Cookie、签名头或用户收藏正文。
- 禁止为了列表展示一次性拉取、渲染全部收藏。
- 禁止单次同步失败时根据缺失结果批量硬删除本地数据。
- 禁止把完整笔记内容长期保存为默认行为。
