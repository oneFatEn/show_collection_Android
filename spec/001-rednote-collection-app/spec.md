# 小红书收藏管理 Android App 规格

日期：2026-06-22

最近更新：2026-08-27

## 背景

「集示」目标是帮助用户重新组织自己的收藏内容。当前优先围绕小红书收藏笔记，完成从登录态获取、收藏同步、自动分类、文件夹式展示到跳回原笔记的闭环。

已有 Electron 原型验证了小红书 Web 登录态、当前用户接口和收藏列表接口可以跑通，但该路线依赖小红书 Web 页面环境和非官方接口，存在稳定性、合规性和安全边界风险。

## 用户目标

用户希望在自己的 Android 手机上：

- 登录自己的小红书账号。
- 同步自己的收藏笔记。
- 让 App 根据笔记标题、正文、标签、封面等信息自动分类。
- 以类似文件夹的方式浏览收藏。
- 点击某条收藏后，能打开小红书并跳转到对应笔记。
- 在本地保留已同步内容，便于离线浏览、搜索和后续整理。

## 核心流程

```text
首次打开 App
  -> 用户进入小红书登录 WebView
  -> WebView 内完成登录
  -> App 确认当前登录用户
  -> App 拉取收藏列表第一页
  -> App 保存笔记 ID、分类关系和轻量展示缓存
  -> App 执行分类
  -> 用户进入文件夹式收藏首页
  -> 点击分类文件夹
  -> 查看笔记列表
  -> 点击具体笔记
  -> 拉起小红书 App 或浏览器打开对应笔记
```

## 功能需求

### FR-001 登录态获取

App 应提供内嵌 WebView，让用户在小红书 Web 页面中自行登录。登录态应保留在本 App 的 WebView CookieStore 中。

验收标准：

- 用户完成登录后，App 可以识别已登录状态。
- App 可以获取当前用户的 `user_id` 和昵称。
- App 不读取或展示用户密码。
- App 不尝试读取小红书官方 App 沙盒中的登录态。

### FR-002 收藏同步

App 应支持分页同步用户自己的小红书收藏笔记。

验收标准：

- 首次同步能获取第一页收藏笔记。
- 当接口返回 `has_more=true` 时，App 能继续通过 `cursor` 加载下一页。
- 同步过程应可中断、可重试。
- 重复同步时应避免重复插入同一笔记。

### FR-003 本地持久化

App 应在本地保存收藏笔记 ID、分类结果、同步状态和用户修正。收藏内容本体应尽量只保留用户本地需要的最小索引，不保存完整笔记正文。

验收标准：

- 断网后仍可浏览已同步的分类结构和笔记 ID 列表。
- App 重启后分类和笔记列表不丢失。
- 用户手动调整分类后，下次自动分类不能直接覆盖人工修正。
- 本地分类关系应支持一个类别 ID 下关联多个笔记 ID。
- 每个分类创建时必须分配全局唯一的本地类别 ID。

### FR-004 动态分类

App 应采用“固定一级分类 + 受控二级分类 + 多标签”的自动分类模型。详细规则以 [`002-constrained-auto-classification/spec.md`](../002-constrained-auto-classification/spec.md) 为准；该规格取代此前基于 embedding 相似度匹配和自由冷启动聚类的分类方案。

验收标准：

- 一级分类固定为十个内容主题加“其他”，AI 不得创建、删除或改名一级分类。
- 每条笔记有且只有一个一级分类、最多一个二级分类，可以有多个标签。
- 二级分类可以自动创建，但只能使用所属一级分类允许的裂变维度，并满足样本数、来源数、去重和每个一级最多 6 个的门槛。
- 未形成稳定二级主题的笔记直接留在一级分类，不强制创建兜底二级分类。
- 首次同步后自动全量分类，后续同步只分类新增和恢复笔记；普通增量流程不得重排已有稳定结果。
- 模型失败、输入不足、返回异常或置信度低于 `0.75` 时进入“待整理”；“其他”是正式分类，两者必须区分。
- 用户手动调整过的分类关系必须人工锁定，不得被自动分类覆盖。
- 全量重新整理必须由用户主动触发，先展示变更预览，确认后才应用。
- Embedding 不参与分类、裂变或类别创建；未来只可用于语义搜索和相似内容推荐。

### FR-005 文件夹式展示

App 首页应以文件夹或分类集合的方式展示用户收藏。

验收标准：

- 用户可以看到分类名称、笔记数量和若干封面预览。
- 首页只展示非空一级分类；用户进入一级分类后可以浏览二级分类和未细分笔记。
- “待整理”作为独立入口展示，不与正式的“其他”分类混用。
- 笔记列表应支持搜索、排序和筛选的扩展空间。

### FR-006 跳回小红书笔记

App 应能从本地笔记条目跳转到小红书原笔记。

验收标准：

- 若已安装小红书，优先尝试打开小红书 App。
- 若无法打开 App，则降级到浏览器打开 Web 链接。
- 跳转失败时展示明确错误，不丢失当前浏览位置。

### FR-007 收藏状态收敛

App 应在每次同步后让本地笔记 ID 集合与用户当前小红书收藏状态收敛。

验收标准：

- 如果用户取消收藏，后续同步应从本地分类关系中移除对应笔记 ID。
- 如果笔记下架、隐藏或接口不再返回，后续同步应软删除对应笔记 ID，活跃列表不展示，但保留状态记录供用户清理或排查。
- 删除策略需要避免单次网络失败导致大面积误删。

## 非功能需求

### 数据安全

- 登录态、Cookie、用户收藏索引和展示缓存默认只保存在用户设备本地，除非用户明确开启云同步或在线模型分类。
- Cookie 只保留在 WebView CookieStore，不写入 Room、DataStore、日志、崩溃上报或剪贴板。
- 第一版本地优先存储笔记 ID、分类关系、同步状态和必要展示缓存；不长期保存完整笔记正文、大图、评论或互动数据。
- 已确定采用轻量缓存。标题、摘要、封面 URL 等用于卡片渲染的元数据作为可清理缓存保存；封面图片文件按缓存策略管理，不作为不可删除核心数据。
- 清除展示缓存不能破坏笔记 ID、分类关系和软删除状态。
- 设置页必须提供清除 WebView 登录态、清除本地分类/笔记索引、清除展示缓存和清除图片缓存的入口。
- 敏感数据不写入普通日志。日志不得包含 Cookie、接口签名头、完整接口响应、完整 raw JSON、用户账号标识、笔记正文。
- 本地数据库如保存用户标识、笔记 ID、分类关系，应预留 SQLCipher 或 Android Keystore 加密方案；第一版若不加密，必须在发布说明中明确本地存储边界。

### 性能

- 分类首页和分类内列表必须使用分页/懒加载，不能一次性把全部收藏渲染到 UI。
- 分类统计和列表查询必须依赖数据库索引，不能在 UI 层全量扫描后分组。
- 同步写库必须批量事务化，避免每条笔记单独提交造成卡顿。
- 同步、分类、缓存刷新必须在后台协程执行，不阻塞主线程。
- 图片加载必须使用缩略图尺寸和磁盘缓存，列表中不加载原图。
- 展示缓存和图片缓存必须有上限和清理策略，避免长期占用设备存储。
- 同步过程应可中断、可重试，并展示进度；失败不能影响已有本地浏览。

### 稳定性与可维护性

- 小红书 Web 接口和页面结构变化时，同步模块应隔离失败，不影响本地浏览。
- 分类、分页、去重、数据库迁移、软删除收敛应可单元测试。
- 把小红书 Web 接入、分类引擎、本地数据、UI 展示解耦。
- 产品第一阶段面向个人及小范围内测；仍需在隐私说明、数据清除、第三方平台依赖和失败降级上给用户明确预期。

## 明确不做

- 不获取他人账号数据。
- 不读取小红书官方 App 私有沙盒。
- 不做批量爬取、公开分发或商业化数据采集。
- 不把小红书登录凭据上传到第三方服务。

## 待澄清

- 分发范围已确定为个人及小范围内测，近期不以上架应用商店为目标。
- 自动分类方案已由 [`002-constrained-auto-classification/spec.md`](../002-constrained-auto-classification/spec.md) 和 [`ADR-0001`](../../docs/adr/0001-constrained-hierarchical-classification.md) 确定。
- 已接受用户必须在 App 内 WebView 重新登录小红书。
- 是否需要导出 Markdown、Obsidian 或 CSV 作为第一版功能？
- 是否需要多账号支持？
