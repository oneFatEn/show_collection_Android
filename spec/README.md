# Spec 文档目录

本目录用于沉淀「集示」Android App 从需求到实现过程中的规格、调研、技术决策和开放问题。

## 工作方式

参考 GitHub Spec Kit 的 Spec-Driven Development 思路，按以下顺序推进：

1. `spec.md`：描述用户要什么、为什么要做、验收标准是什么，避免过早写具体实现。
2. `research.md`：记录技术调研、约束、风险和可选方案。
3. `plan.md`：把需求转换为技术架构、模块边界、数据模型和执行策略。
4. `quality.md`：记录性能、数据安全、数据保留和禁止事项。
5. `tasks.md`：在方案稳定后拆成可执行任务。

当前项目仍处于探索期，因此先建立 `001-rednote-collection-app/` 作为第一个产品规格。

## 当前规格

- `001-rednote-collection-app/`：小红书登录态获取、收藏同步、动态分类和文件夹式展示。
